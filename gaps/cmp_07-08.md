# Nitro PDF Pro vs SmartDocs: sections 7 (Comments / Annotations / Review) and 8 (Forms)

Source compared: `D:\pdf\SmartDocs-project-v0.4.0` on branch `main`. This was a read-only review: nothing was built and nothing was changed.

**Path prefix:** `E/` stands for `D:\pdf\SmartDocs-project-v0.4.0\app\src\main\java\com\smartdocs\editor\`. Strings are in `app\src\main\res\values*\`.

**Status meanings:**
- **HAVE:** the logic exists and a UI entry reaches it.
- **PARTIAL:** it exists, but some options are missing.
- **CODE-ONLY:** the logic exists, but no UI reaches it.
- **MISSING:** a search found nothing. The grep terms are listed.
- **N/A-ANDROID:** not applicable on Android.

**How section 8 is judged:** Nitro's form options are design-time options. SmartDocs runs most of them when the user fills an existing PDF (it has a Rhino AcroJS engine and AF functions). It cannot set most of them when building a form. When fill-time support works but no design-time UI exists, the row is **PARTIAL** and says "fill-time HAVE / authoring MISSING".

**Video annotations:** these are being rebuilt on another branch. They are listed once only (row 7.34).
