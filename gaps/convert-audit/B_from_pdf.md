# Convert audit — Group B: PDF → other formats (+ Cv6Results, Cv6Save, ExtractImagesScreen)

Scope: pdf_xlsx, pdf_pptx, pdf_images, pdf_long_image, extract_images, pdf_txt, pdf_html, pdf_rtf, pdf_md, pdf_epub, pdf_csv, pdf_odt, pdf_ods, pdf_odp, pdf_svg, pdf_tiff, pdf_bmp, pdf_ps, pdf_eps, pdf_xps, pdf_xml, pdf_access_txt, pdf_html_set, pdf_xml2003, plus pdf_docx (crash/cancel/memory/options/batch only).
Paths are relative to `app/src/main/java/com/smartdocs/editor/`. Read-only audit; no project files changed.

## Verified by running

JVM harness (pure Kotlin, project sources `Export7.kt`, `FlowDoc.kt`, `Images6.kt` copied unchanged) in `scratchpad/convaudit/hb/` (`src/Harness.kt`, `St.kt`, `Dig.kt`), compiled with K2JVMCompiler, JDK 17, `-Xmx1g`:

1. **TIFF size (B07)**, one A4 page at the default 200 dpi (1654×2339, the pagePictures size):
   - text-like page: RGB 1280 KB, GRAY 1044 KB, BW 108 KB per page;
   - photo-like page: RGB 602 KB, GRAY 356 KB, BW 49 KB.
   - So 300 text pages ≈ 375 MB (RGB) / 306 MB (gray) of encoded strips, before the BAOS + `toByteArray` copies.
2. **PS (B08)**: a 143 KB page JPEG becomes 182 K chars of ASCII85 (364 KB as UTF-16). 300 pages ≈ 106 MB String, before StringBuilder growth and the writeText byte copy.
3. **PdfXml range (B04)**: with Export7Run.xml's call logic, range 5-7 gives 3 `<page>` elements with NO lines; range "1,3" gives page 1 OK and page 2 (= source page 3) empty.
4. **Xml2003 (B13)**: `12d, NaN, Infinity, 007, 1,5, 0x1p3, 1e400, -0` are all emitted as `ss:Type="Number"` (raw text "12d", "NaN", "0x1p3"…, "1,5" → "15"); `٣٤` is emitted as String.
5. **Arabic locale digits (B12)**: `Locale("ar")`, `"page_%03d.html".format(1)` gives U+0070 … U+005F **U+0660 U+0660 U+0661** … (also ar-SA, ar-EG). Android ICU behaves the same.
6. **Long image (B06)**, `Images6.stitch` at the default 110 dpi:
   - 10 pages → 909×12860;
   - 13 pages → 909×16718 (WebP limit exceeded);
   - 50 pages → 909×64300 (222 MB ARGB);
   - 100 pages → 581×82200 (JPEG limit exceeded);
   - 300 pages → 371×157500.
7. **XPS viewbox (B05)** arithmetic: a 595 pt page rendered to 1652 px gets Viewbox width 793.3, so 0.48 of the picture is visible if the viewer treats the JPEG as 96 dpi (Android JPEGs carry no DPI).

Not run: Android-only paths (PDFium rendering, PdfBox-Android text extraction needs the AAR glyph-list assets; it failed on plain JVM with "GlyphList not found"). The chemistry sample (`ملخص_المساند…الوحدة_الأولى.pdf`, 45 pages) is a text PDF with small images, not a scan.
