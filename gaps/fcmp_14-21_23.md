# Foxit PDF Editor 14 vs SmartDocs: sections 14–21 and 23

Read-only comparison against `main` (`3a1c44a`) in `D:\pdf\SmartDocs-project-v0.4.0`. Code paths are relative to `app/src/main/java/com/smartdocs/editor/`. Strings: `res/values/` holds Arabic and `res/values-en/` holds English. Nothing was built or run.

The Nitro files (`gaps/cmp_01-06.md`, `cmp_07-08.md`, `cmp_09-15.md`, `cmp_16-24.md`) were reused where a Foxit row matches a Nitro row ("see cmp_xx"). Every HAVE row that has extra Foxit options was re-checked in the code. Foxit-only rows were searched in the code directly.

**Statuses:**
- **HAVE:** implemented and reachable from the UI.
- **PARTIAL:** some options are missing; the note says which.
- **CODE-ONLY:** the logic exists but nothing in the UI calls it.
- **MISSING:** searched for and not found; the grep terms are listed.
- **N/A-ANDROID:** desktop-only, or not feasible on Android.
- **IN PROGRESS:** video rows. The in-page video player is being built on branch `feature/inline-video`. Parts of it are already on main (`core/annot/VideoPdf.kt`, `ui/reader/annot/VideoHost.kt`, `InPageVideoLayer.kt`, `VideoDialogs.kt`, `res/values*/strings_video.xml`), but these rows were not judged.

**Importance** means importance for a phone or tablet PDF app.

**Main UI entry points:**
- **Edit content mode:** `ui/reader/ReaderToolbars.kt:177` → `ui/edit/EditModeHost.kt`. Logic is in `ui/edit/EditController.kt` and the panels in `ui/edit/EditPanels.kt`.
- **Annotation tools:** `ui/reader/annot/Toolset.kt:40-72`.
- **Edit5 hub:** Tools card `e5_hub` → `ui/edit5/Edit5Hub.kt:26-48`.
- **Organize:** `ui/pages/OrganizeScreen.kt`.
- **Optimizer:** `ui/tools5/OptimizeExportScreens.kt:63-100`.
- **Recipes:** `ui/tools5/RecipesScreen.kt`.
