# خادم المستندات المتصلة

عامل Cloudflare يربط نسخ مستند PDF بمالكه: تتبُّع الإصدارات، تنبيه «يوجد إصدار أحدث»، عدد مرات الفتح،
قائمة القرّاء مع الموافقة/الحظر، وإلغاء الوصول. في «الوضع المحمي» يُشفَّر الملف (AES-256) بمفتاح يحفظه الخادم،
فلا يُفتح إلا لقارئ مسموح له (مع مهلة عمل دون اتصال يحددها المالك).

## النشر
1. `npm install -g wrangler` ثم `wrangler login`.
2. `wrangler kv namespace create DOCS` وانسخ المعرّف إلى `wrangler.toml`.
3. (اختياري) `wrangler r2 bucket create smartdocs-connected` وأزل التعليق عن `r2_buckets` (لإصدارات أكبر).
4. `wrangler secret put APP_TOKEN` (كلمة سر طويلة).
5. `wrangler deploy`.
6. في `cloud.properties`:
   ```
   connectedUrl=https://smartdocs-connected.<name>.workers.dev
   connectedToken=<نفس APP_TOKEN>
   ```
7. أعد بناء التطبيق.

## كيف يعمل
- المالك يسجّل المستند ← يحصل على معرّف من 12 حرفاً يُكتب داخل الملف (ذيل الملف، بيانات المستند، XMP) + مفتاح المالك (يبقى في جهازه).
- كل فتح للملف في التطبيق يرسل المعرّف وبصمة الملف ← يعيد الخادم: مسموح/بانتظار الموافقة/محظور/أُلغي، وأحدث إصدار.
- نشر إصدار جديد: مع الملف (يستطيع القرّاء تنزيله) أو بالبصمة فقط (تنبيه دون تنزيل). تُحفظ ملفات آخر 5 إصدارات.

## الحدود الصريحة
- الإلغاء يمنع القراءة فقط للملفات **المحمية**، وبعد انتهاء مهلة العمل دون اتصال أو عند الفتح التالي متصلاً.
- من حصل على المفتاح يستطيع فتح تلك النسخة في أي قارئ PDF؛ الملفات غير المحمية تبقى مقروءة دائماً.
- كل إصدارات المستند تتشارك مفتاحاً واحداً.
- هوية القارئ معرّف عشوائي لكل تثبيت + الاسم الذي يضعه في الإعدادات؛ مسح بيانات التطبيق يُنشئ «قارئاً» جديداً.
- إن أعيد تثبيت التطبيق على جهاز المالك يُفقد مفتاح المالك، فلا يمكن نشر إصدارات جديدة لذلك المستند.
