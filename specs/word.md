# Word-Processor Reference Analysis: Microsoft Word for Android, plus Desktop, Google Docs and WPS Writer

> **Purpose.** This is a reference analysis of word-processing features for a native Android (Kotlin / Jetpack Compose) editor that opens, edits and saves `.docx` (OOXML, ECMA-376 / ISO/IEC 29500) files. It lists features commonly found in mobile and desktop word processors. For each one it records how the feature behaves, where it usually sits in the UI, and what implementing it involves.
>
> **Baseline.** Microsoft Word for Android: the standalone "Microsoft Word" app and the Word experience inside the Microsoft 365 Copilot app, 2025–2026 builds. Word for Windows/Mac (desktop) and Word for the web are included where a feature works on a phone or tablet. Google Docs for Android and WPS Office (Writer) for Android are included only where they offer something Word for Android lacks.
>
> **Date of analysis:** 2026-10-24.

## 0. Legend and conventions

### 0.1 Availability codes (column **Avail**)

| Code | Meaning |
|---|---|
| **A** | Available in Word for Android, on both phone and tablet |
| **AT** | Android tablet or large screen only. Covers the full ribbon, plus features hidden on phones. |
| **A~** | Available on Android, but with fewer options than desktop |
| **W** | Word for the web (also usable in a mobile browser) |
| **D** | Desktop only (Windows/Mac). Not in Word for Android. |
| **iOS** | Present on iPhone/iPad but not confirmed on Android |
| **Lic** | Requires a Microsoft 365 subscription or Copilot licence. Free use is view/basic-edit only on screens over 10.1" or for commercial use. |
| **?** | Availability varies by build, region or channel (Insider), or could not be confirmed from public documentation |

### 0.2 Other columns

* **D (Difficulty)**: **S** = small (under ~3 dev-days, simple XML), **M** = medium (layout and UI work, several parts), **L** = large (a layout-engine change, complex OOXML, or a server or AI dependency).
* **Off**: whether the feature can run fully offline. **Y** = yes, **N** = needs a network or cloud, **P** = partly (for example, a local fallback with degraded quality).
* **Arabic UI label**: a suggested label, in Modern Standard Arabic as used in Arabic-localised office suites.
* **OOXML** abbreviations: `w:` = WordprocessingML main namespace; `a:` = DrawingML; `wp:` = DrawingML WordprocessingDrawing; `pic:`, `wps:` (shapes), `wpg:` (groups), `m:` = OMML (Office Math); `w14:`/`w15:`/`w16*:` = Word 2010+/2013+/2016+ extensions; `mc:` = Markup Compatibility; `r:` = relationships.

### 0.3 OOXML package map (referenced throughout)

| Part (typical path) | Content type / role | Touched by |
|---|---|---|
| `[Content_Types].xml` | Content-type registry for every part | Every new part or media type |

| `word/theme/theme1.xml` | `a:theme` → `a:clrScheme`, `a:fontScheme` (`+mj-lt`, `+mn-lt`, `+mn-cs` for complex script), `a:fmtScheme` | Theme colours and fonts |
| `word/header{n}.xml`, `word/footer{n}.xml` | `w:hdr` / `w:ftr`, referenced from `w:sectPr/w:headerReference` with `w:type=default|first|even` | Header/footer, page numbers, watermark |
| `word/footnotes.xml`, `word/endnotes.xml` | `w:footnote` / `w:endnote` (ids -1 and 0 are the separator and continuation separator) | Footnotes, endnotes |

| `word/charts/chart{n}.xml` + embedded `.xlsx` | DrawingML charts (`c:chartSpace`) | Charts |
| `word/diagrams/*` (data, layout, quickStyle, colors, drawing) | SmartArt (`dgm:`) | SmartArt |
| `word/glossary/document.xml` | Building blocks, Quick Parts, AutoText | Cover pages, Quick Parts |
| `word/customXml/*`, `customXml/item{n}.xml` | Custom XML data, bibliography sources (`b:Sources`), content-control bindings | Citations, forms |
| `word/webSettings.xml` | Web options | Rarely edited |
| `docProps/core.xml` | Dublin Core: title, creator, lastModifiedBy, revision, created/modified | Properties, Save |
| `docProps/app.xml` | Application, Pages, Words, Characters, Lines, Paragraphs, TotalTime | Word count cache, Save |
| `docProps/custom.xml` | Custom properties, sensitivity labels (MSIP_Label_*) | Properties, labels |
| `docProps/thumbnail.jpeg` | File-picker thumbnail | Save |

**Engineering principle (round-trip fidelity).** Any element, attribute or part the editor does not understand must be kept byte-for-byte (opaque passthrough), including `mc:AlternateContent`, unknown `w14`/`w15`/`w16` attributes and `w:rsid*`. Only nodes the user actually edited are rewritten. Most features below assume an internal model of the form *Document → Section[] → Block[] (Paragraph | Table | SDT | opaque) → Inline[] (Run | Drawing | Field | Hyperlink | FootnoteRef | Comment anchors | opaque)*, plus a layout engine that supports two modes: *Print Layout* (paginated) and *Mobile View* (reflow).

## 22. Architecture notes for the Kotlin/Compose implementation (cross-cutting)

1. **Package I/O.** Use `java.util.zip` (ZipFile for random access) with streaming StAX/XmlPullParser (`org.xmlpull`, built into Android) for document.xml, since it can exceed 50 MB. Keep unknown parts as raw bytes. On write, regenerate only the dirty parts, update `[Content_Types].xml`/rels, and re-zip into a temp file, then rename it. Keep `mimetype`-like ordering ([Content_Types].xml first) for compatibility with strict readers.
2. **Model.** Use an immutable, persistent tree (for example kotlinx.collections.immutable) to make undo/redo and change diffs cheap. Store run properties as interned `RPr` objects (flyweight) so that large documents stay within memory.
3. **Style resolution.** Precompute effective paragraph and run properties lazily, cache them per (styleId, numbering, table-conditional) key, and invalidate them on style edits.
4. **Text layout.** Use Android `android.graphics.text.LineBreaker` / `MeasuredText` (API 29+) for shaping and line breaking (it handles Arabic shaping, bidi and font fallback through `Typeface.CustomFallbackBuilder`). Do custom paragraph composition for tabs, floats (exclusion zones), drop caps and justification. Kashida needs custom glyph insertion via a HarfBuzz port.
5. **Rendering.** Draw on a Compose `Canvas` per page or tile, virtualised with `LazyColumn` of pages (Print Layout) or of paragraphs/blocks (Mobile View). Draw the IME caret and selection in an overlay. Implement input through a custom `InputConnection` (`BaseInputConnection`, via `PlatformTextInputModifierNode` in Compose) so that composing text, Gboard Arabic and voice input all work.
6. **Track changes** is a mode of the editing-operations layer. Each primitive operation (insertText, deleteRange, setRunProp, setParaProp, splitParagraph, mergeParagraphs, insertTableRow…) has a tracked variant that writes revision wrappers.
7. **Fields** need an evaluation pass after pagination (PAGE, NUMPAGES, PAGEREF, TOC) that iterates to a fixed point, because TOC length changes pagination.
8. **Testing corpus.** Collect real-world docx from Word (Win/Mac/Web/Android), Google Docs exports, WPS and LibreOffice, plus Arabic government and school templates, and run round-trip (open → save → diff XML) and visual regression (render → compare with reference PDFs).
